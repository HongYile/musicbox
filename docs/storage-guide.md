# 音乐存储与格式策略指南

> 回答三个问题：下载后用什么格式存？便宜的云存储选谁？怎么保证随时能快速解码听歌？

## 1. 格式：无损压缩就是 FLAC 本身

- **FLAC / ALAC 就是为音乐而生的无损压缩格式**：体积是 WAV 的 50–70%，解码开销极低（比 MP3 还省电），任何播放器原生支持。
- **musicbox 的下载策略（已实现）**：B站 Hi-Res 流本来服务器给的就是 FLAC → 原样保存 `.flac`；192K 及以下 AAC → 原样保存 `.m4a`。**全程不转码**。
- **不要做的事**：
  - AAC → FLAC：有损转无损，体积变大 3-5 倍，音质零提升；
  - ZIP/RAR 再压缩：FLAC 已经压过了，再压收益 <3%，还破坏了可流式播放性；
  - 追求"更小"而转 Opus：适合流媒体，但那是**有损**的，和"无损存档"目标冲突。
- 结论：**存档=FLAC 原样，听歌=直接播 FLAC**，没有中间商。

## 3. 快速解码听歌

- FLAC 解码是 CPU 最轻松的任务之一，二十年前的主流 CPU 都能实时解码 10 倍以上速度——不存在"解码瓶颈"。
- 流式播放可行性：media_kit(mpv) 原生支持 HTTP Range 流式播放 FLAC/m4a——R2 公开读或签名 URL 直接当播放源，**不用先下载**。
- 本地播放：musicbox 下载页已支持播本地文件。

## 4. 防"音源失效"策略

- B站老视频降质、QQ 音乐下架是常态 → **喜欢即下载**（Hi-Res 优先，播放器/列表页都有下载按钮）；
- 元数据（歌单/下载记录）坚果云同步，换机/重装不丢；
- 音乐文件后续可选上 R2，实现"云端无损曲库、随处流式听"。
